## ✅ 너의 코드 개선 내역 요약

| 항목                     | 개선 전                                       | 개선 후                                                        | 개선 이유                                |
| ------------------------ | --------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------- |
| **1. 입력 파싱**         | `for` 루프 안에서 `input[i + 1]` 등 직접 접근 | 한 번에 `map(row => row.split(" ").map(Number))`로 숫자 배열화 | 반복 split/map 호출 최소화 & 깔끔한 구조 |
| **2. 테스트케이스 추출** | 반복문 안에서 `input[3 * i + k]` 접근         | `tests.slice(3 * i, 3 * i + 3)`로 묶어서 구조분해              | 가독성 향상, 추출 실수 방지              |
| **3. n 추출 방식**       | 문자열 → 숫자 변환 필요                       | `nRow[0]`에서 바로 추출                                        | 구조분해 오류 방지, 안정성 향상          |
| **4. `Math.max` 사용**   | `Math.max(a, b)` 반복 호출                    | `a > b ? a : b`로 대체                                         | 성능 최적화 (tight loop에서 연산 최소화) |
| **5. 출력 처리**         | 매 루프마다 `console.log()` 호출              | 결과를 모아서 `join("\n")` 후 한 번만 출력                     | I/O 비용 절감, Node.js 기준 효율적       |

---

## ✅ 개선 전후 비교 예시 (핵심)

### 🔻 Before

```js
console.log(Math.max(topMax, botMax, noneMax));
```

### ✅ After

```js
results.push(Math.max(prevTopMax, prevBotMax, prevNoneMax));
// ...
console.log(results.join("\n"));
```

---

### 🔻 Before

```js
let newTopMax = top[j] + Math.max(botMax, noneMax);
```

### ✅ After

```js
let maxTopChoice = prevBotMax > prevNoneMax ? prevBotMax : prevNoneMax;
let newTopMax = top[j] + maxTopChoice;
```

## ✅ 보너스: 네이밍 관점 정리

| 변수명                                    | 의미                         | 추천 이유        |
| ----------------------------------------- | ---------------------------- | ---------------- |
| `prevTopMax`, `prevBotMax`, `prevNoneMax` | 이전 열에서의 최대 점수      | 명확한 역할 표현 |
| `newTopMax`, `newBotMax`, `newNoneMax`    | 현재 열에서 갱신된 최대 점수 | 시간 흐름 표현   |

## ✅ 전체 총평

너의 최종 코드는 **시간 복잡도 O(N), 공간 O(1) 상태 유지**,
게다가 **가독성과 유지보수성까지 챙긴 정석적인 최적화 코드**야.

> 복습할 땐 위 표들을 참고하면 어떤 이유로 무엇을 개선했는지 명확하게 기억날 거야.

필요하다면 이 개선 과정을 마크다운 문서나 노션용 요약으로도 정리해줄 수 있어.
